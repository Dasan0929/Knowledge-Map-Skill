# 最小认知闭环：设计与审核

## 全图的终点

先完成一句话：“学生完成本路线后，能够在【情境】中【解释／区分／完成任务】，并指出【适用边界】。”这就是 context.closure_goal。只选与当前需求相关的维度，不强行添加职业建议、自我诊断或历史考据。

围绕终点反推模块，检查问题／动机、基本概念、机制／联系、使用／辨析、边界／迁移是否有必要支撑。它们不是固定五章，可由一个模块覆盖多个维度。不把全领域目录当最小闭环。

## 节点的两部分

每个节点的 content 是“短标题 + 换行 + 范围说明”，例如：

> 四种功能与两种态度
区分感觉、直觉、思维、情感处理的任务，以及内倾和外倾的定向方式，建立八种功能态度的组合框架。

core_question 则是：

> 为什么四种功能能形成八种功能态度，而不能简单理解成八种能力排名？

内容告诉学生要学什么；核心问题定义这一块最终要解释什么。避免一个长问题塞进多个独立任务。简短且主题单一时 content 可只写一段；不要以关键词或标题替代必要范围。

每个顶层模块应足以进一步讲解多个小点，但本层不列这些小点。应用例子属于内容支持，不独立制造节点。结构合理不等于理论已被实证验证；遇有版本分歧，在必要内容和 context.assumptions 中保留适用语境。

## 递归是否有意义

子图的目标就是父问题，范围就是父内容。子模块不是复述父标题，而是必要的解释步骤。内部走查一次：假设学生能回答所有子问题，是否足以回答父问题？若仍缺桥梁，就修补；若出现无关内容，就删去。

以荣格八维的“知觉功能辨析”为例，子图可围绕感觉与直觉的任务差异、同功能的态度差异、相同情境中的比较三块形成闭环，不需要单独为每个术语生成一张卡。此例仅说明结构，不作为人格评估依据。

停止条件：已经能够直接讲清；无法再分出两个独立有意义的模块；细分不会改善父问题的回答。深度本身不代表学习质量。

## agent 的语义审核

- 路线终点具体、与用户目标一致。
- 模块合起来足以支撑终点，无明显必要环节遗漏。
- 每个模块均有内容范围与可作答的核心问题。
- 前置表示回答问题所必需的依赖，不表示教材顺序或心理因果。
- 每个节点能成为独立子主题，但尚未将其细节倾倒到本层。
- 子图不改变父问题，也不将兄弟节点的全部内容偷渡进来。

这些审核不能仅用节点数或代码测试证明。
