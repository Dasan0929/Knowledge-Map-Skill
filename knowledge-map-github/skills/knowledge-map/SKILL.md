# Knowledge Map v0.3

## 任务与交付

将用户的学习目标及实际可用的学习者背景，转成有最小认知闭环的知识骨架。成功交付必须包含**文件及渲染预览**，不能只回复路线列表或 JSON 文本。

- `map.json`：唯一的知识内容与学习状态来源；每个节点恰好五字段。
- `context.json`：本层闭环目标、范围、记忆来源和父子地图关系。
- `learning-map.canvas`：符合 JSON Canvas 1.0 的可编辑画布。
- `learning-map.html`：离线预览，支持缩放、平移、点选卡片及已登记子地图导航。

默认在任务的输出位置为主题新建独立目录；有指定目录则遵循用户要求。已有主题使用已知路径，不能仅凭同名就覆盖其他学习项目。不自动安装 skill、不写入未知 Obsidian vault，也不声称实现隐藏持久化、双向同步或下游自动调用。

## 先读什么

- 内容协议与执行命令：[references/protocol.md](references/protocol.md)，首次写文件前阅读。
- 生成或修改节点时：[references/closure-guide.md](references/closure-guide.md)。

- 正式字段定义：[map.schema.json](references/map.schema.json)、[context.schema.json](references/context.schema.json)。

## 工作流

### 0. 判断范围与起点：生成地图之前

先判断输入能否确定一个可达到的学习终点，不能一收到主题就画图。

- **宽泛且目标不明**，如“我想学习 AI”“我想学习高中数学”：先澄清方向、用途或具体困难。给 2–4 个容易选择的入口；必要时问 2–3 个简短问题了解起点。不要先产出一张巨大地图再要求用户选择。
- **方向明确但起点不清**：用自述或一两个低压力情境问题了解已有理解。观察回答中的解释依据，不按是否认识术语机械分级；这只是路线定位，不构成正式通关或掌握认定。
- **范围和起点足够明确**：直接起草，不要求用户填写完整画像。
- **明确要领域概览**：可为大领域生成概览地图；闭环目标限定为识别核心问题、分支及联系，不声称可学完该领域。

每轮澄清通常不超过三个问题，优先问最影响路径的内容。已有对话或记忆能够回答时不重复问。用户不确定时可提供一个默认入口让其选择，不循环盘问。此时还没有地图，不伪造 pending_confirm、空节点地图或 `.canvas` 文件。

### 1. Draft / INIT：形成最小认知闭环并展示

1. 确定 `target`、`closure_goal` 与范围。closure_goal 写成可观察的终点：能解释、辨别或完成什么；不能只是“掌握主题”。没有提出自我测型、职业应用等目标时不要擅自加入。
2. 顶层设计 **5–8 个**平铺的模块级节点。每个节点只呈现**内容与核心问题**；内容包含短标题和 1–2 句范围说明。以问题起源、基本模型、关键机制、可用场景及边界审核整体闭环，不机械套成固定章节。
3. 检查每个节点：它支撑哪个必要环节？删去是否造成断裂？核心问题能否作为后续讲解入口与通关依据？覆盖不能靠无穷扩张获得。
4. 写入合法状态 `pending_confirm`；新节点为 `todo`。生成两份 JSON，运行校验和构建工具，打开或提供**渲染后的 HTML**，并提供 `.canvas` 链接。支持 Obsidian 时可在已知目标中打开 Canvas；没有相应工具时明确给文件，不把文件链接说成已显示图形。
5. 简短邀请用户调整；本轮不授课、不自行锁定。

### 2. Refine / REFINE：在同一份状态上协商

- 用户说“已经会了／删掉”时可删、合并或精简。需要的支撑合并到其他模块，或将用户明确具备的基础记为背景假设；不能留下悬空依赖或暗藏新必修。
- 按明确偏好调整内容；顶层仍为 5–8 个模块，不能不断追加或拆碎凑数。确与用户明确要求冲突时协商，不擅自忽略其要求。
- 未改变认知任务的节点保留 ID 和已有 status；新任务或核心问题实质变化时重置为 todo。删除 ID 不分配给别的新任务。掌握认定由后续模块负责；明确要求保留但跳过可标为 skipped。
- 内容变化后进入 pending_confirm、增加 context.revision；更换闭环目标时重新审核整条路线。保存修改前的有效状态到主题目录的 `history/`，保留回退依据。
- 重建 Canvas 和预览，使用旧 Canvas 尽量保留卡片横向位置。对已有子地图按父节点指纹检查；父任务改变的子地图标为待重做，不自动沿用。
- 展示更新的图和一句改动说明。若用户明确授权“按这些修改后直接开始”，可以将这条授权作为修改版本的锁定依据；有未解决的实质歧义时再澄清，不重复索取已经给出的授权。

### 3. Lock & Handoff / LOCK：锁定与移交

用户明确认可当前路线，或已明确授权按指定修改后开始时，复查后仅把 map_status 改为 locked；节点内容、顺序、依赖与学习状态保持不变。重新构建，确保图上状态一致。

后续模块读取 `map.json` 和必要的 `context.json`，依据依赖确定可进入节点。提供文件路径及有效版本即可，不复制一套不同内容的交接地图。没有下游接入时仅说明路线已确定，不声称已调用其他 agent。锁定不是通关，不能把 todo 自动改为 learning 或 mastered。

### 4. 按需递归：把节点作为子主题

当用户进入某个已锁定节点且确需进一步规划时，以父节点的 content 为子主题范围、core_question 为该层 closure_goal，运行同样的范围判断与协商流程。

- 每层独立保存；节点内仍禁止 children。父子关联存在 context，不改变五字段协议。
- 子地图通常 **2–5 个**模块；这是 v0.3 的局部展开约定，避免强迫每层都再分 5–8 点。各子模块的核心问题应共同支撑父问题，加入内容不得超出父任务。
- 若已能直接用简短解释和示例处理，或拆不出两个有独立作用的模块，**停止制图并移交讲解**。不为了递归而无限生成文件，不预先展开整棵树。
- 父地图只维持原有 5–8 个学习节点，登记子图后可点击进入；不把子图知识点堆回顶层。

## 呈现约定

默认先展示图，再简述闭环终点和必要假设。卡片只显示学习内容、核心问题及自然语言状态；内部 ID、原始 JSON、XML 标签和协议说明不打印到聊天。箭头统一为**前置 → 后续**；无依赖分支可并排，不为了美观伪造顺序。学习状态以文字和颜色同时表达。

HTML 预览和 Canvas 是生成视图；Canvas 手动改字不会反向写入 map.json，重建时以状态为准。预览点选、缩放不会改变学习状态。普通确认自然交流，不引用 skill 规则解释等待。

## 校验与失败处理

用脚本检查数据结构、引用、循环、数量、状态转换和父子关系；再由 agent 检查闭环是否成立、依赖是否必要、问题是否可作答。工具不能替代教学判断。

渲染后检查实际图形：内容可读、卡片不重叠、文字不截断、箭头可追踪，分支与状态一致。优先修复，工具缺失时保留合法 JSON 和 Canvas 并说明预览未完成，不拿纯文字冒充成功。两次具体修复仍失败时保留最后有效文件并报告原因。只有文件真实写入且命令成功后才声称已生成。
